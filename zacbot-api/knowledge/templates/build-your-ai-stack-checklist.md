# Build Your AI Stack Checklist

A progressive setup guide for fractional executives building Claude Code into their practice.

---

## Week 1: Context (Your First CLAUDE.md)

- [ ] Install Claude Code (desktop app, mobile app, or terminal)
- [ ] Create a working directory for your business (e.g., `~/Business/`)
- [ ] Write your first CLAUDE.md answering these 5 questions:
  - [ ] What do you do? (2-3 sentences)
  - [ ] Who do you serve? (Target customer profile)
  - [ ] What do you deliver? (Core outputs)
  - [ ] How should Claude communicate? (Voice, tone, formatting)
  - [ ] What should Claude never do? (Guardrails)
- [ ] Add file editing rules (always read before writing, preserve manual updates)
- [ ] Add a navigation section mapping your directory structure
- [ ] Start a conversation in that directory and verify Claude reads the file
- [ ] Use Plan Mode (Shift+Tab) as your safety net while learning

**Checkpoint:** Claude should be able to describe your business, your target customer, and your core deliverables without you saying a word.

---

## Week 2: Connections (Your First MCP)

- [ ] Identify your highest-friction context switch (usually email or CRM)
- [ ] Set up your first MCP server:
  - [ ] Gmail - "Check my inbox for anything from [client]"
  - [ ] Google Docs - "Create a document with this deliverable"
  - [ ] Notion - "Show me my notes from last week"
  - [ ] Your CRM - "Show me my pipeline"
- [ ] Test a real workflow: draft an email, check your pipeline, or create a document
- [ ] Notice the difference. One environment. Zero context switching.

**Checkpoint:** You should be able to complete at least one real task without leaving Claude.

---

## Week 3: Workflows (Your First Skill)

- [ ] Identify your core deliverable. What do clients pay you for?
- [ ] Map the steps of that deliverable (inputs, process, outputs)
- [ ] Give Claude past examples of that deliverable
- [ ] Ask Claude to help structure it as a repeatable workflow
- [ ] Create a skill file (`.claude/skills/[name]/SKILL.md`)
- [ ] Test the skill with a real or simulated engagement
- [ ] Refine based on output quality

**Checkpoint:** You should be able to trigger your core deliverable with a slash command and get a solid first draft.

---

## Month 2: Depth

- [ ] Create client-level CLAUDE.md files for active engagements
  - [ ] ICP definitions
  - [ ] Messaging frameworks
  - [ ] Engagement tracking
  - [ ] Call notes and decisions
- [ ] Add a second MCP server (pick your next highest-friction tool)
- [ ] Build a second skill (prospecting, content, or ops)
- [ ] Start using `/reflect` at session end to capture corrections and preferences
- [ ] Start using `/debrief` to persist decisions and tasks

**Checkpoint:** Claude should know your business, your clients, and your methodology. Corrections you make once should stick permanently.

---

## Month 3: Compound

- [ ] Start your Pattern Library
  - [ ] Create a `Patterns/` directory
  - [ ] After each engagement, extract 2-3 reusable patterns
  - [ ] Format: Name, Source, Context, Insight, Application, Evidence
- [ ] Review your CLAUDE.md files. Are they bloated? Trim what's no longer relevant.
- [ ] Build a content skill (LinkedIn posts, newsletter, proposals)
- [ ] Add a third MCP if needed
- [ ] Run an extraction exercise on your last 2-3 engagements:
  - [ ] What worked that should be standard?
  - [ ] What patterns keep appearing?
  - [ ] What should my templates include that they don't?

**Checkpoint:** Your second engagement should be noticeably faster than your first. The system is compounding.

---

## Month 6+: Scale

- [ ] Full CLAUDE.md hierarchy (business, project, client levels)
- [ ] 3-5 active skills covering your core workflows
- [ ] 3+ MCP connections eliminating context switches
- [ ] Pattern Library with 10+ documented patterns
- [ ] Content flywheel: client work generates content automatically
- [ ] Reflect loop: corrections improve the system permanently
- [ ] Consider: what's your next skill? What workflow still has manual steps?

**Checkpoint:** Each unit of work makes the next one easier. You're not just using AI. You're operating inside it.

---

## Quick Reference: What to Build When

| If you're spending time on... | Build this |
|-------------------------------|-----------|
| Retyping context every session | CLAUDE.md file |
| Switching between Claude and email | Gmail MCP |
| Switching between Claude and CRM | CRM MCP (Attio, HubSpot, etc.) |
| Manually creating the same deliverable | A skill for that deliverable |
| Making the same correction twice | `/reflect` to persist the fix |
| Losing track of session decisions | `/debrief` at end of session |
| Forgetting what worked last engagement | Pattern Library entry |
| Creating content from scratch | Content skill + style guide |

---

## Common Mistakes to Avoid

1. **Trying to build everything at once.** Start with one file. Add one connection. Build one skill. Let each layer prove its value.
2. **Skipping context and jumping to skills.** Skills without context produce generic output. CLAUDE.md first, always.
3. **Not extracting patterns.** The work you do today should make tomorrow's work faster. If it doesn't, you're not extracting.
4. **Bloating your CLAUDE.md.** More is not better. Claude has a context window. Put in what matters. Remove what doesn't.
5. **Treating AI output as final.** First drafts should be fast, not perfect. Build the review into your process.
6. **Going in circles.** If you've said "fix it" three times and it's not fixed, the problem is context, not the fix. Stop. Add better instructions. Start a fresh session.
